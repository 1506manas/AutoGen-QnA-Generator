# AutoGen Question-Answer Generation Agent (POC)

A small proof-of-concept that uses **AutoGen** + **OpenAI** to generate
questions and detailed answers on a topic, then verifies each reference
URL with a Python tool before returning it.

## What it does

Given:
```json
{ "topic": "Agentic AI", "complexity": "Advanced", "question_count": 5 }
```

It produces, for each question:
- The question
- A detailed answer
- A reference URL that has been **checked** (not just guessed) before being returned

## Setup

1. **Install Python packages**
   ```bash
   pip install -r requirements.txt
   ```

2. **Add your OpenAI API key**
   Copy `.env.example` to `.env` and fill in your key:
   ```bash
   cp .env.example .env
   # then edit .env and set OPENAI_API_KEY and TAVILY_API_KEY
   ```

3. **Run it**
   ```bash
   python agent.py
   ```
   This runs the sample input already in the script (`Agentic AI`,
   `Intermediate`, 3) and writes the result to `output.json`, also
   printing it to the console.

4. **To use your own input**, edit the `sample_input` dictionary at the
   bottom of `agent.py`.

## Architecture (brief)

There is one AutoGen agent and one shared Python tool:

```
 User input (topic, complexity, count)
            |
            v
 +----------------------+  
 |   qa_generator        |
 |  (AssistantAgent)     |
 |  - writes Q&A pairs   |
 +----------------------+ 
            |
            v
 +-------------------------------+  
 |   Tool Call                   |
 |  (search_and_verify_tool)     |
 |  Find URL and Validate        |
 +-------------------------------+  
             |
             v
   Final JSON (question, answer, verified reference or null)
            |
            v
      Final Output
```

**The tool — `search_and_verify_tool(questions: List[str])`**
- Sends a list of n number of question generated by Agent.
- Generate URL with the reference of the Questions.
- Call a function `verify_reference` to validate the URL generated by Tavily.
- `accessible = True` if the server returns HTTP 200.
- `relevant = True` if the webpage content is relevant to the question.
- The agent is instructed to retry with a different URL (up to 3 times)
  if verification fails, and to fall back to `null` if it still can't
  find a working reference.

## Notes / possible improvements

- The relevance check is done by the LLM model, which check the actual relevance of the question and the 
  content of the webpage from Tavily.
- I am using `gpt-4o-mini` model for this agent and for verification of URLs.
- In a single tool integration, we are solving 2 problems. (URL search, Again Search if fail, Verify Relevance of the URL with Question)
